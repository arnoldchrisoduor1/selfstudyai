Explain how Raft ensures leader completeness during network partitions, and analyze why a minority partition cannot commit log entries independently.

edit_note My Answer Submitted at 00:38:12

“A minority partition cannot commit entries because it cannot gather votes from a majority of nodes for AppendEntries RPCs. Raft requires a majority quorum ((n/2) + 1) to commit an entry. The leader in the minority partition will continue accepting client requests if connected, but will never receive confirmation from a majority, so the entries remain uncommitted until partition heals.”

warning Omission Detected

Did not address the Election Restriction rule that guarantees the newly elected leader contains all previously committed entries via quorum intersection.

menu_book Model Answer Course Canon Solution

Raft enforces Leader Completeness via the election restriction: a candidate must have a log at least as up-to-date as any majority voter (measured by higher term, then longer log index). During a partition:

  1. Minority Partition: Any leader in a minority can receive requests but cannot achieve majority consensus on AppendEntries, preventing log commits.
  2. Majority Partition: Will elect a new leader with higher term number. Because any two majorities intersect by the pigeonhole principle, at least one node in the election quorum contains all previously committed entries.
  3. Reconnection: When healed, the old minority leader discovers the higher term, steps down to follower, and overwrites conflicting uncommitted entries.
